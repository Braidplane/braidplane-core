## Inventory and delivery

Run `task notices` after changing dependencies, toolchains or covered assets.
It refreshes [THIRD_PARTY_NOTICES.txt](../THIRD_PARTY_NOTICES.txt) using the pinned
Go wrapper and installed frontend packages matching the lockfile. `task lint`
compares the generated bytes with the committed inventory.

The inventory combines backend/frontend/migrator/CLI package graphs for Linux
and macOS amd64/arm64 with CGO disabled and enabled, and CGO-disabled Windows
amd64/arm64 CLI graphs. It retains
named LICENSE, COPYING, NOTICE, THIRD-PARTY-NOTICES, AUTHORS, COPYRIGHT and PATENTS
files, plus `.license` sidecars, at module roots and in selected package ancestry,
including selected Go standard-library ancestry. Complete legal texts
are retained rather than reducing combined licenses to a single heading.
The collector also retains distinct leading Go/C-style legal comment headers
from selected dependency source files. This preserves file-level attribution
and copied-code notices that a module-root license alone can omit. It stops at
implementation text and rejects source paths outside the module or Go root.
It also includes ODCS, vendored frontend notices, icon license/disclaimer files,
and the locked Tailwind CSS and daisyUI input licenses. This is a superset of
individual binary dependencies, not an assertion that every listed component
is embedded in each artifact.

The notice inventory separately retains root legal documents for the pinned
Templ, Enumer, GoWrap, oapi-codegen and SQLC generators selected through
`tools/go.mod`. These are generation-input records, not assertions that the
compiler programs are embedded in each binary or that they own the output.
Keep the emitted generator headers and source inputs with generated files.
The checked CSS retains its Tailwind version/MIT marker; both the locked CSS
input licenses and the separate vendored browser-component notices are included.
The generated inventory retains upstream whitespace and line endings; its Git
attributes preserve those bytes. The generation freshness check validates this
file instead of applying source-code whitespace formatting to upstream text.

`task build-go` copies LICENSE, NOTICE and THIRD_PARTY_NOTICES.txt into
`out/licenses/`, alongside the local executable bundle. Validation CI does not
upload that bundle. All four Docker targets carry those files in `/usr/share/licenses/braidplane/`. The
frontend additionally retains adjacent static-asset/icon notices. Keep the
license directory with any redistributed executables; copying a binary alone
does not carry its notices.

The same bundle and images include the ten pinned upstream MPL module source
ZIPs under `licenses/sources/` or `/usr/share/licenses/braidplane/sources/`.
[MPL_SOURCES.sha256](../MPL_SOURCES.sha256) identifies their exact bytes;
[SOURCE_AVAILABILITY.txt](../SOURCE_AVAILABILITY.txt) tells recipients how to
retrieve them without starting the application. The packaging task verifies
each module version against the selected module graph and checks every ZIP
hash. Docker checks the same hashes against its downloaded module cache.
The inventory freshness check rejects a changed set of MPL module versions.

The three scratch images also preserve the CA-certificate and timezone package
copyright files from the exact builder stage, with the GPL text referenced by
the CA package, in `/usr/share/licenses/braidplane/runtime/`. These notices do
not replace the remaining source-delivery review for other runtime components.
All four images also include Debian's CA-certificate source package and .dsc
for version `20250419~deb12u2` under `sources/runtime/`. Docker verifies the
installed package version and both pinned download hashes; the .dsc's checksum
was checked against the retained archive containing `mozilla/certdata.txt`.
The source files come from the [Debian snapshot archive](https://snapshot.debian.org/package/ca-certificates/20250419~deb12u2/).
The Debian backend retains its installed packages' own `/usr/share/doc/` and
`/usr/share/common-licenses/` material. Run `task container-sources image=IMAGE`
against the exact built backend image to collect its Debian source companion
under `out/container-sources/`. The task queries the installed binary/source
package mapping in a disposable network-disabled, read-only container, resolves
each exact source version through Debian Snapshot, and verifies downloaded file
identities and source-descriptor SHA-256 checksums. The resulting archive and
JSON receipt identify the immutable image digest and source-file inventory.

Distribute the matching companion with the backend image and a clear recipient
source location. A locally prepared archive is not an uploaded source endpoint.
The task covers the installed Debian package database; separately review local
modifications, unpackaged image files, required build inputs and any additional
obligations. It does not verify Debian signing keys or claim full reconstruction
of the image. Changed image digests require a new companion and receipt.

This is the source-delivery mechanism for the listed, unmodified dependencies,
following [MPL 2.0 section 3.2](https://www.mozilla.org/en-US/MPL/2.0/).
It does not cover local replacements, modified dependency source or sources
omitted from an upstream module ZIP; those require separate review.

The legacy standalone CLI archive script remains a separate packaging path;
its dependency collector is reused here. Its historical export manifest is not
the current core release manifest or evidence of a qualified standalone release.

## Remaining exact-candidate review

This inventory and delivery change does not complete release clearance. The
release receipt must identify the immutable source revision, artifact hashes,
platform/build settings, reviewer, owner decision, delivered notice/source
package and unresolved conditions. Review at least:

* Contributions, copied source and source-header notices, differently named
  legal documents, nested vendored material and generated output. The named-file
  and leading-comment collector does not discover every possible obligation,
  including legal statements after implementation code or in embedded data.
* MPL-covered dependency source against the actual build, including any local
  changes, nested modules or required files omitted by upstream ZIPs. Confirm
  the distributed artifacts retain all source ZIPs and recipient instructions;
  previously retained review archives are not substitutes for delivered files.
* Actual compiled binaries and generated CSS against the inventory, including
  compiler/runtime inputs and any additional embedded legal material.
* Container OS packages, Git/OpenSSH, CA roots and timezone data. The backend's
  installed OS packages and scratch images' copied runtime data require their
  own exact-image inventory and any applicable source/notice delivery.
* Vendor marks against their exact usage and guidelines. Simple Icons' license
  does not grant trademark permission; see the [icon policy](../brand/icons/data-sources/README.md).
  The [vendor review](../brand/icons/data-sources/RELEASE_REVIEW.md) identifies
  the two official marks and seven provisionally retained connector logos. Unused vendor
  artwork and recoloured variants are excluded from the current release tree.
* Any additional architecture, CGO use, build tags, replacement or dependency
  change outside the inventory's declared matrix.

Do not describe this file or a passing freshness check as legal classification,
complete compatibility review, rights clearance or publication permission.
