# S3 data source

Explicit compiled operations may use the versioned
[resource scope policy](../RESOURCE_SCOPES.md) for CSV/JSON rows with a fixed
endpoint, region, bucket and prefix plus declared relative-key selectors.
Ordinary S3 execution alone makes no such confinement claim.

## Purpose and best-fit use cases

Use the S3 connector to read from or write to AWS S3 or S3-compatible object stores such as MinIO. It is suited for durable object routing, CSV/JSON/Excel workbook ingestion and export, native file/blob pass-through, and pipeline sink output that should land in object storage.

## Transport security

Custom endpoints require HTTPS. Redirects cannot downgrade HTTPS to HTTP.
See the shared [transport encryption policy](../DATA_SOURCES.md#transport-encryption) for the local fixture exception.

## Shared capabilities

S3 supports the shared data-source lifecycle, parameterized object reads/writes,
provider-listing pagination for introspection, and pipeline source/sink roles.
See the [capability matrix](../DATA_SOURCES.md#capability-matrix) and
[payload compatibility matrix](../DATA_SOURCES.md#pipeline-payload-compatibility-matrix)
for the canonical cross-connector contract.

Create an S3 connection from **Data Sources → Add Data Source → S3-compatible storage**.
The form can test the draft connection before saving. Credentials are write-only;
the browser retains the entered values across draft connection tests without the
server returning them. Private endpoints are shown only when enabled for the deployment.

## Required config fields

| Field | Required | Type | Default | Notes |
|---|:---:|---|---|---|
| `region` | yes | string | - | AWS region or S3-compatible signing region |
| `bucket` | yes | string | - | Default bucket used by connection tests, introspection, and operations that omit `bucket` |
| `endpoint` | no | string | AWS S3 endpoint | S3-compatible endpoint URL for providers such as MinIO |
| `prefix` | no | string | - | Key prefix used for introspection and resolving relative operation keys |
| `force_path_style` | no | boolean | `false` | Required by many S3-compatible providers |
| `timeout_seconds` | no | integer | 5 | Request timeout in seconds (1-300) |
| `allow_private_hosts` | no | boolean | `false` | Requires private host access to be enabled for the deployment; hosted/default deployments reject `true` |

## Credentials

The first S3 slice supports static access-key credentials plus an optional temporary session token. Other authorization modes, such as workload identity, STS AssumeRole, web identity/OIDC federation, and runtime/default credential-chain support, remain future work.

| Field | Required | Notes |
|---|:---:|---|
| `access_key_id` | yes | S3 access key ID |
| `secret_access_key` | yes | S3 secret access key |
| `session_token` | no | Temporary-session token |

Credentials are encrypted at rest and never returned in API responses. See [DATA_SOURCES.md - Shared credential lifecycle](../DATA_SOURCES.md#shared-credential-lifecycle).

## Schema introspection

See the shared [file discovery contract](FILE_DISCOVERY.md) for object metadata,
raw-file entries, inference diagnostics, and import budgets.

Schema refresh/import queues a worker job that recursively lists objects below
the configured `prefix` and samples supported structured objects. Normal
data-source detail pages and `GET /schema` read cached metadata only; they do
not list or sample objects. CSV, JSON, and Excel workbook objects use the
shared `FileSchemaResponse` shape (`schema_type: file`, `type: s3`).

Every listed object is retained with safe MIME type and size metadata when
known. Opaque file/blob objects have no fields and raw bytes are never stored
as schema. CSV field names come from the header row and all inferred CSV fields
use type `string`; JSON and workbook samples may infer their supported
structural fields. Objects that cannot be read or whose samples cannot be
parsed safely remain as entries with no fields and a warning diagnostic.

The import uses the shared schema item, byte, and time quotas; the current
defaults are 1,000 entries, 10 MiB of schema bytes, and a 30-second connector
timeout. Exceeding a listing quota fails the import and leaves the previous
schema cache unchanged rather than persisting a partial result.

## Query and operation model

A query defines an object operation:

The Queries page supports inspecting and editing saved S3 operations as JSON.
The complete statement is retained, including content, metadata and overwrite
settings. Current query settings can differ from a run's immutable operation.

**Read** (`operation: read`): reads the object at `key` and returns rows for `csv`, `json`, and `spreadsheet`, or a native `file` payload for `format: file`. Format is detected from the object key extension unless specified explicitly. CSV supports delimiter and header controls. Spreadsheet mode supports Excel workbook files, selects one worksheet, optionally crops to an A1 range, and normalizes the selected cells into rows.

**Write** (`operation: write`): serializes the runtime-provided `input` payload to the object at `key`; direct saved queries may alternatively provide inline `content`. JSON output accepts structured object or array payloads only. CSV output accepts row-object arrays or raw CSV text. Spreadsheet output accepts row-object arrays and writes a workbook. Native file output uses `format: file` and writes bytes without CSV/JSON/spreadsheet parsing. `overwrite` controls whether an existing object can be replaced.

Supported operation fields include:

- `key` (required)
- `bucket` (optional override of the configured bucket)
- `operation` (`read` or `write`, default is `read`)
- `format` (`auto`, `csv`, `json`, `file`, or `spreadsheet`)
- `delimiter` and `has_header` for CSV handling
- `sheet`, `range`, and `has_header` for spreadsheet handling
- `content_type` and `metadata` for writes
- `overwrite` for writes

The `{{param_name}}` template syntax is supported in `bucket`, `key`, `sheet`, `range`, `content_type`, and metadata values. Relative keys are resolved below the configured `prefix`; absolute keys and `..` traversal are rejected. Reserved runtime placeholders such as `{{runtime.run.date}}`, `{{runtime.run.datetime}}`, and `{{runtime.sink.replay_identity}}` are injected automatically for query execution and sink key overrides.

Execution returns:

- `column_names` - field names from CSV/spreadsheet headers or JSON keys
- `rows` - array of objects (field name to value)
- `row_count` - number of rows read
- `written_rows` and `written_bytes` for writes
- `file` - safe metadata for native file reads/writes; raw bytes are omitted from API responses and persisted run diagnostics

## Pipeline relevance

**As a source**: the pipeline step uses `operation_type: s3`. CSV, JSON, and spreadsheet objects are normalized to rows before downstream transform steps see them; `format: file` produces a native file payload for pass-through sinks.

S3 source steps do not support incremental checkpoint contracts in the first object-store slice. They are full-object reads during pipeline validation and runtime execution. Pipeline validation rejects `watermark` and `cursor` incremental contracts for `operation_type: s3`.

**As a sink**: the pipeline step uses `operation_type: s3`. Sink config supplies `key` and optional `bucket`, `format`, `delimiter`, `has_header`, `sheet`, `range`, `content_type`, `metadata`, and `overwrite`. Upstream payloads are serialized to CSV, JSON, or spreadsheet format and written to the target object, or written byte-for-byte when the sink operation uses `format: file`.

Both CLI definition validation and API-backed validation require a non-empty
string at `sink.config.key`, including when the selected saved or inline write
operation already contains a key. The operation defines the write; terminal
sink config supplies its delivery parameters. A successful connection test
checks connection readiness and does not validate a pipeline's sink definition.

```yaml
- kind: sink
  slug: store-orders
  sink:
    input: fetch-orders
    data_source_ref: archive
    operation_type: s3
    operation_inline:
      type: s3
      operation: write
      key: "{{key}}"
      format: json
      input: "{{input}}"
    config:
      key: exports/orders.json
      format: json
      overwrite: true
    idempotency_class: naturally_idempotent
```

Use `naturally_idempotent` only when the conditions below hold. Configuration
failures detected before dispatch do not claim a delivery attempt. S3 statement
decoding, parameter binding, and serialization finish before the durable effect
claim at the provider write boundary. With isolated execution workers, a
preparation-only request validates the same immutable connector input before
runtime claims the effect and submits execution. Older workers reject the new
`prepare_s3_write` request kind without executing it; upgrade workers before
relying on this protocol. Workers receive no ledger capability. Completed ledger
effects skip provider execution; the selected operation is still prepared. Once a write
has been dispatched, an error may leave its outcome unknown; reconcile the
provider outcome before replaying an ambiguous write.

An S3 sink can declare `naturally_idempotent` when its source and transforms
produce deterministic bytes, it sets `overwrite: true`, and it uses a stable
key such as `runs/{{runtime.sink.replay_identity}}/output.json`. Queue
redelivery and operator replay reuse that identity, so the repeated write
overwrites the same object and is exactly-once-equivalent from the object
consumer's perspective. A changing key, nondeterministic content, or
`overwrite: false` is not this contract; use `deduplicated_by_ledger` or mark
the operation `unsafe` instead. See the sink replay contract
for all replay classes.

## Security

Private IP ranges and loopback endpoint hosts are blocked by default to reduce SSRF (Server-Side Request Forgery) risk. Hosted/default Braidplane rejects customer S3 data source payloads that set `allow_private_hosts: true`. The `self-hosted` profile rejects this broad switch and currently supports public destinations for this connector; local fixtures may opt into private hosts. See the [private-host policy](../DATA_SOURCES.md#private-host-access). Custom endpoint sockets dial vetted literal IPs while retaining the URL hostname for TLS, HTTP Host, and SigV4 signing; redirects are revalidated before they are followed. Credentials are write-only and are passed to the provider client only as in-memory runtime payloads.

## Known limitations

- Query result pagination is not supported. Object reads return one bounded object payload per execution.
- Object listing pagination is used for recursive introspection, but public
  continuation-token APIs for browsing large buckets remain future work.
- Structured writes check for an existing object before writing, so concurrent writers can race. Native-file streaming uses conditional multipart completion for `overwrite: false`; the provider must support that condition.
- Server-side encryption headers, storage class, object tagging, ACLs, user-controlled multipart operations, object version selection, presigned URLs, and bucket management are not supported. Native-file streaming uses multipart internally; see [its limits](../NATIVE_FILE_STREAMING.md#supported-operations).
- Native file payload bytes remain runtime-only. Historical preview/download and general artifact retention require future storage policy work.
- Non-static S3 authorization modes remain deferred.
- OpenDocument spreadsheets, workbook rendering, spreadsheet editing UI, multi-sheet merge behavior, formula evaluation, and preservation of existing workbook artifacts are not supported.

See [connector support levels](../../docs-public/connectors/support-levels.md) for available operations, connector status and provider requirements.
